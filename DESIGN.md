# cu-overlay design notes

## Why a helper process

Claude Desktop draws the Computer Use glow and cursor in a transparent Electron window. On Wayland an app window cannot be placed above everything, cannot be made click-through reliably, and cannot be positioned on another output. wlr-layer-shell's overlay layer gives exactly that, but Electron does not speak it. So the bridges (which already ship one static binary per session type) grow an `overlay` subcommand, and this crate is its shared implementation.

## Decisions

- **Surfaces.** One layer surface per show (overlay layer, anchored to all edges, exclusive zone -1, keyboard interactivity none, empty input region, namespace `claude-cu-overlay`) carries the glow or rim. Three synchronized subsurfaces carry the badge, the press ring and the arrow, stacked in that order (empty input regions too). Moving the arrow redraws only a 192 px logical buffer and its position lands atomically with the parent commit; the ring is separate so it stays at the press point while the arrow glides away, as upstream's `#cursor-press` does.
- **Confined to the shown output.** A wl_subsurface is not clipped to its parent, so a subsurface placed past the layer surface's edge is drawn on whatever output that lands on. Each subsurface box is therefore intersected with the output (`geom::sub_box`): a point that is not on the output unmaps the arrow or ring (the controller keeps the pose, so `move` to the right output shows it again), and a box that straddles the edge gets a smaller buffer cut at the edge, positioned at the clipped origin, with the anchor moved inside it. Cutting the buffer (rather than a viewport source rectangle) works with and without wp_viewporter and keeps the surface itself inside the output, so nothing can spill; the only cost is that a drop shadow near the cut does not see the silhouette beyond it, which is invisible because that part is off the output anyway. One non-fatal `arrow outside output <name>` error per command tells the caller its point was not drawn.
- **Badge.** `badge.rs` mirrors upstream's `#badge` CSS and its `badge-center-to-corner` keyframes (5 % in, hold to 88 %, slide to the corner, ends at opacity 0; one `cubic-bezier(0.4, 0, 0.2, 1)` per keyframe interval, applied to opacity, `top`/`left`, the `translate(-50%, -50%)` and the scale together) and the dot's `dot-pulse`. Timing is pure functions of the milliseconds since the `show`, so the controller only keeps a start instant and the backend places the pill from the output size. The pill is painted with tiny-skia (pill path, border as an even-odd ring, dot) and the text with `ab_glyph` outlines of one embedded subset of Noto Sans Medium (OFL 1.1).
  - *Font rasterizer, not a mask.* A pre-rendered alpha mask of the English string would be a few KB but fixes the text, the size and the scale: the pill is drawn at 1.4 x the output scale, shrinks continuously to 0.8 during the slide and must be crisp at any fractional scale, and callers can pass a localized string (`badgeText`). Rasterizing 30 glyphs per frame costs microseconds, so no glyph cache is needed. The price is about 150 KB of code and a 34 KB font (Basic Latin to Cyrillic, no kerning); the alternative of a runtime system-font lookup would need fontconfig (C) and is not static.
  - *One surface, drawn per frame.* The subsurface keeps the size of the pill at its largest scale for the whole flash (so its buffers are reused), and the pill is drawn inside it at the current scale and sub-pixel offset; the box follows the pill in whole logical pixels, clamped to the output (a box that does not fit the output is not drawn), so it never reaches a neighbouring output. The slide and flash-in are paced by frame callbacks, the hold by the 30 Hz timer the glow pulse uses (the dot is the only thing that changes), and after 6 s the surface is blanked and nothing runs. Opacity (flash fade times the layer's fade times a capture hide) goes through the alpha modifier when there is one, else it is baked into the pixels.
  - *Capture.* The badge is part of scope `all` (the scene's opacity is 0, the surface is blanked) and not of scope `cursor`: it is not a cursor and it is short-lived, and the rim or glow it belongs to stays too. A caller that must keep it out of every screenshot sends `all`.
  - *Reduced motion* never shows it (upstream leaves `#badge` at opacity 0 there). Every `show` restarts the flash or, without `badge`, clears it, as upstream's page does on each show.
- **Subsurfaces are blanked, not unmapped.** To hide the arrow or ring (off the output, capture hide, ring finished) the overlay commits a fully transparent buffer of the same size in place instead of attaching null. On the first CI run (sway 1.9 / wlroots 0.17.1, ubuntu-24.04) an arrow unmapped by a null attach stayed on screen in two cases where the scene kept animating (a press running after an off-output jump, a glide continuing off the output), while every buffer commit repainted correctly; the exact sway 1.9 code path was not reproduced locally. A blanked subsurface stays mapped, invisible and click-through until its next draw, and is destroyed with the rest on `hide`.
- **No null attach on the layer surface.** Attaching a null buffer unmaps a layer surface and re-attaching later is a protocol error ("layer_surface has never been configured", seen in the prototype). `hide` destroys the surfaces after the fade, and a later `show` creates new ones; a capture hide without alpha-modifier attaches a 1x1 transparent buffer scaled up by the viewport.
- **Alpha modifier for opacity.** Fades, the glow pulse and the capture hide change `wp_alpha_modifier_surface_v1` multipliers and commit, with no redraw. The glow is drawn once at the pulse's peak keyframe and dimmed to 0.70 (the ratio of base to peak edge alpha) for the low point. The pulse commits at about 30 Hz on a timer; glides, presses and fades are paced by frame callbacks; nothing at all runs while the scene is static.
- **Glow math.** CSS inset box-shadow with blur `b` is a Gaussian with sigma b/2 (the CSS spec value; a measurement of upstream's own rendering on X11 matched it: alpha 0.52 / 0.20 / 0.044 at 0 / 50 / 100 px versus 0.55 / 0.19 / 0.045 from the model). The inside of the box blurred is separable, so each band is two 1D erf profiles; only the edge bands within 3.5 sigma are computed.
- **Arrow.** The transform reproduces upstream's element chain exactly (tilt pivot (2.2, 1.6) in viewBox units, 22 px SVG for 18 units at (-3, -2), bump around the hotspot, body scale 2 (1 + 0.06 lift)). drop-shadow's blur length is taken as the Gaussian's standard deviation (SVG `feGaussianBlur` semantics), approximated by three box blurs limited to the arrow's bounding box, with per-thread scratch buffers so a glide does not allocate.
- **Frames come from the caller.** The glide planner (duration from distance, arc, swing and lift springs) stays in the JS side, which already has upstream's function; the overlay plays `[x, y, deg, lift]` frames with linear interpolation, as WAAPI does with upstream's keyframes. The overlay therefore never needs updating when upstream retunes the motion.
- **Coordinates.** Protocol coordinates are global logical (what `screens` reports). Outputs come from `wl_output` (name, mode, transform) and `zxdg_output_v1` (logical position and size); the reported scale is mode / logical size, so 1.5 is exact. The buffer scale is the surface's `wp_fractional_scale_v1` preferred scale, else the output scale through the viewport, else the integer output scale.
- **Two capture scopes.** `all` zeroes every multiplier (or swaps in transparent buffers); `cursor` detaches only the arrow and ring subsurfaces, which takes effect with the parent commit, so the rim or glow never blinks. The scene simply leaves the cursor out while a hide is in force; the controller's clocks keep running, so `restore` draws the arrow at its current pose and the ring only if `press_frame` still has a frame for it. `ready` advertises `captureScopes` for feature detection.
- **Capture hide is acknowledged after a `wl_display.sync`** following the commit: the compositor has applied the zero multiplier (or transparent buffer) before any later screencopy or portal screenshot is rendered. It restores itself after 3 s so a caller that dies mid-screenshot never leaves the overlay invisible.
- **Unknown output on `show` is fatal**: exit 2 without surfaces. On `move` it is a non-fatal error and the overlay stays on its current output (a bridge should not need a respawn for a stale display id). An output unplugged while shown is not fatal either: `closed` from the compositor becomes a non-fatal error plus `hidden`.
- **Output layout is pushed.** `ready` lists every output (name, global logical position and size, scale); any later change (wl_output / xdg_output `done`, global removal) re-reads the list and sends an `outputs` event when it differs from the last one sent, so a bridge never has to query again.
- **Parent death** follows cu-abort-watch: `PR_SET_PDEATHSIG` plus a 500 ms check of `CLAUDE_CU_PARENT_PID` (pid + start time) or `getppid`. No signal handlers are needed: the compositor removes the surfaces with the connection on any exit.
- **Testability.** The controller takes `Instant`s as input, so every timing rule (fades, glide playback, ring keyframes, capture auto-restore) is unit tested without a compositor; the renderer is tested on raw buffers; the backend is tested end to end on a headless sway.

## Deferred

- **X11 backend for GNOME** (Mutter has no layer-shell): an override-redirect ARGB window per output with an empty input shape (XShape), behind a cargo feature `x11`, implementing `backend::Backend`. The renderer already writes the 32-bit ARGB visual's memory layout; opacity without an alpha modifier uses the existing fallback path (or `_NET_WM_WINDOW_OPACITY` where a compositor honours it).
- **Pulse fidelity**: interpolating blur radii instead of an alpha multiplier would need a redraw per frame; not worth the CPU.
- **Cheaper shadows**: the lift shadow could be blurred at reduced resolution; about 0.7 ms per arrow frame at scale 1.5 today.
